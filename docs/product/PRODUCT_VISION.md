# 1. Objetivo deste Documento

Este documento define para onde o VemVer está indo.

Ele não deve ser utilizado para descrever apenas o código existente atualmente.

Seu objetivo é registrar:

- a visão de longo prazo;
- o posicionamento desejado;
- a experiência ideal;
- os princípios permanentes do produto;
- os objetivos estratégicos;
- os critérios que deverão orientar novas funcionalidades.

Quando houver dúvida entre duas direções de produto, este documento deverá ajudar a responder:

> Qual decisão aproxima mais o VemVer da plataforma que queremos construir?

---

# 2. Visão Resumida

O VemVer deverá se tornar uma plataforma de descoberta local capaz de compreender o que uma pessoa procura e conectá-la rapidamente às melhores opções disponíveis ao seu redor.

A experiência desejada pode ser resumida em:

```text
EU PRECISO DE ALGO
       ↓
EU DIGO AO VEMVER
       ↓
O VEMVER ENTENDE
       ↓
O VEMVER ENCONTRA
       ↓
EU ESCOLHO
       ↓
EU RESOLVO MINHA NECESSIDADE
```

O usuário não deverá precisar conhecer previamente o nome da loja.

Ele deverá apenas informar o que deseja.

---

# 3. Frase de Direção

> Você não procura. O VemVer encontra para você.

Essa frase não representa necessariamente um slogan publicitário definitivo.

Ela representa a direção da experiência que desejamos construir.

O VemVer deverá reduzir progressivamente o trabalho manual necessário para encontrar algo em uma cidade.

---

# 4. Propósito

Eliminar a distância entre quem procura e quem vende.

De um lado existem consumidores com necessidades.

Do outro existem estabelecimentos que possuem produtos, serviços e soluções.

O VemVer deverá funcionar como a ponte inteligente entre esses dois lados.

---

# 5. Missão

Conectar pessoas ao comércio local através de uma experiência rápida, inteligente, simples, segura e relevante.

---

# 6. Visão de Longo Prazo

O VemVer deverá ser reconhecido como uma das principais plataformas brasileiras de descoberta local.

Quando uma pessoa quiser encontrar:

- um produto;
- uma loja;
- um restaurante;
- um serviço;
- um profissional;
- uma experiência;
- uma solução local;

o VemVer deverá ser uma das primeiras opções consideradas.

---

# 7. Visão para 2031

Até 2031, a direção pretendida é transformar o VemVer em uma referência para descoberta de comércio e serviços locais.

A plataforma deverá evoluir para ser capaz de:

- operar em diversas cidades;
- compreender buscas em linguagem natural;
- localizar estabelecimentos relevantes;
- localizar produtos específicos;
- considerar localização e contexto;
- apresentar reputação e avaliações;
- considerar disponibilidade quando houver dados confiáveis;
- personalizar resultados;
- apoiar decisões de compra;
- gerar oportunidades reais para lojistas;
- oferecer ferramentas comerciais para empresas;
- operar em web e aplicativos móveis.

Essa visão representa direção estratégica.

Não significa que todas essas capacidades já estejam implementadas.

# 8. O Problema que Queremos Resolver

Hoje uma pessoa que procura algo local frequentemente precisa pesquisar em vários lugares.

Exemplo:

```text
Google
   ↓
Instagram
   ↓
WhatsApp
   ↓
Maps
   ↓
Marketplace
   ↓
Indicação
   ↓
Site da loja
```

Esse processo é fragmentado.

O VemVer deverá reduzir esse caminho.

A experiência desejada é:

```text
VEMVER
   ↓
"O QUE VOCÊ PROCURA?"
   ↓
RESULTADOS RELEVANTES
```

# 10. O VemVer que Queremos Construir

O VemVer futuro deverá ser mais do que uma listagem de lojas.

Ele deverá compreender contexto.

Exemplo:

```text
"Quero hambúrguer perto de mim"
```

não deve ser interpretado apenas como uma busca pela palavra:

```text
hambúrguer
```

O sistema deverá progressivamente compreender que o usuário provavelmente está procurando:

- alimentação;
- estabelecimentos compatíveis;
- proximidade;
- opções relevantes naquele momento.

Outro exemplo:

```text
"Preciso consertar meu notebook"
```

deverá evoluir para encontrar estabelecimentos relacionados a:

- informática;
- assistência técnica;
- manutenção;
- notebooks.

A plataforma deverá melhorar sua capacidade de transformar linguagem humana em descoberta estruturada.

---

# 11. Experiência Ideal do Consumidor

A experiência ideal começa com simplicidade.

Ao entrar no VemVer, uma das perguntas centrais deverá ser:

> O que você procura hoje?

O consumidor não deverá precisar conhecer categorias internas do sistema.

Ele deverá poder escrever naturalmente.

Exemplos:

```text
Quero açaí

Preciso de uma assistência para notebook

Onde encontro roupa infantil?

Tem algum restaurante perto de mim?

Quero comprar um presente para minha mãe

Onde encontro pastel folhado?

Preciso de uma loja de informática
```

O sistema deverá transformar essas necessidades em resultados úteis.

---

# 12. Menos Filtros, Mais Compreensão

Filtros continuarão sendo úteis.

Porém, a experiência principal não deverá depender do consumidor aprender a utilizar dezenas de filtros.

A inteligência da plataforma deverá progressivamente compreender aspectos como:

- categoria;
- produto;
- intenção;
- proximidade;
- preço;
- atendimento;
- delivery;
- horário;
- características específicas.

Somente informações realmente disponíveis e confiáveis deverão ser utilizadas.

O sistema não deverá inventar dados.

---

# 13. Experiência Ideal do Lojista

Para o lojista, o VemVer deverá representar visibilidade e oportunidade comercial.

A experiência deverá ser simples o suficiente para que uma pequena empresa consiga utilizar a plataforma sem equipe técnica.

O lojista deverá poder:

- criar sua conta;
- cadastrar sua empresa;
- adicionar informações;
- cadastrar produtos;
- adicionar imagens;
- manter informações atualizadas;
- receber avaliações;
- acompanhar desempenho;
- aumentar sua exposição através de planos;
- utilizar ferramentas para melhorar sua presença local.

Com o tempo, o painel poderá evoluir para oferecer inteligência comercial.

---

# 14. Valor para o Consumidor

O consumidor deverá perceber valor principalmente através de:

## Economia de tempo

Encontrar algo mais rapidamente.

## Relevância

Receber opções relacionadas ao que realmente procurou.

## Proximidade

Encontrar alternativas disponíveis na sua região.

## Confiança

Visualizar informações, avaliações e reputação.

## Descoberta

Encontrar estabelecimentos que talvez não conhecesse anteriormente.

## Simplicidade

Não precisar utilizar diversos aplicativos para resolver uma necessidade local.

---

# 15. Valor para o Lojista

O lojista deverá perceber valor através de:

## Visibilidade

Ser encontrado por pessoas próximas.

## Intenção

Aparecer para consumidores que estão procurando algo relacionado ao que vende.

## Presença digital

Possuir uma página estruturada dentro da plataforma.

## Descoberta de produtos

Permitir que seus produtos participem das buscas.

## Reputação

Construir avaliações e confiança.

## Dados

Compreender como sua presença está performando.

## Crescimento

Utilizar recursos pagos quando fizer sentido para seu negócio.

# 16. Descoberta Acima de Diretório

Uma regra importante de produto é:

> O VemVer não deve evoluir apenas como um diretório de empresas.

Um diretório responde:

```text
"Quais lojas existem?"
```

O VemVer deverá responder cada vez melhor:

```text
"Qual loja pode resolver o que eu preciso?"
```

Essa diferença é estratégica.

---

# 17. Inteligência Artificial

A IA será uma ferramenta importante, mas não será dona das regras do VemVer.

Princípio:

> A IA interpreta. O sistema decide.

A inteligência artificial poderá ajudar a:

- interpretar mensagens;
- identificar intenção;
- compreender termos;
- reconhecer contexto;
- normalizar buscas;
- futuramente auxiliar na personalização.

Porém, decisões relacionadas a:

- segurança;
- acesso;
- banco de dados;
- ranking;
- cobrança;
- permissões;
- regras comerciais;

continuarão sob responsabilidade do backend.

---

# 18. IA Não Deve Inventar Realidade

O VemVer não deve apresentar como verdade informações que não possui.

Exemplo:

Se ainda não existe informação confiável sobre:

```text
delivery
```

o sistema não deverá afirmar que determinado estabelecimento realiza delivery.

O mesmo vale para:

- horários;
- estoque;
- preço;
- disponibilidade;
- serviços;
- promoções.

A IA deverá trabalhar sobre informações confiáveis do sistema.

---

# 19. Ranking e Confiança

O ranking é uma das partes mais importantes da visão do VemVer.

O usuário deverá confiar que os primeiros resultados possuem relação real com sua busca.

Princípio permanente:

> Relevância vem antes de monetização.

Uma loja patrocinada poderá possuir vantagens comerciais dentro de limites definidos.

Porém, uma loja patrocinada irrelevante não deverá superar uma loja diretamente relacionada ao que o consumidor procurou.

---

# 20. Ordem Conceitual do Ranking

A direção conceitual deverá preservar:

```text
1. RELEVÂNCIA

2. CONTEXTO DA BUSCA

3. DISTÂNCIA
   quando solicitada ou pertinente

4. QUALIDADE / REPUTAÇÃO / SCORE

5. CRITÉRIOS COMERCIAIS PERMITIDOS
```

A fórmula real poderá evoluir.

O princípio não deverá ser perdido.

---

# 21. Localização

Localização será um dos principais diferenciais do VemVer.

O produto deverá compreender que necessidades locais possuem contexto geográfico.

Exemplo:

```text
"Quero uma pizzaria"
```

pode produzir uma experiência diferente de:

```text
"Quero uma pizzaria perto de mim"
```

A distância deverá ser considerada quando fizer sentido.

---

# 22. Cidade por Cidade

A estratégia inicial deverá priorizar qualidade antes de expansão descontrolada.

O crescimento poderá seguir:

```text
JOINVILLE
   ↓
VALIDAR PRODUTO
   ↓

   ↓
VALIDAR MONETIZAÇÃO
   ↓
EXPANDIR PARA NOVAS CIDADES

REPETIR MODELO
```

O VemVer deverá aprender profundamente com uma cidade antes de tentar operar em centenas.

A cidade piloto poderá ajudar a validar:

- aquisição de lojistas;
- categorias;
- qualidade dos dados;
- geolocalização;
- ranking;
- planos;
- retenção;
- comportamento dos consumidores.

A arquitetura não deverá ficar presa a Joinville.

# 24. Expansão Regional

Depois de validar o modelo inicial, o produto poderá avançar para cidades próximas ou regiões estrategicamente escolhidas.

A expansão deverá considerar:

- capacidade operacional;
- número de lojas cadastradas;
- qualidade do catálogo;
- demanda dos consumidores;
- suporte;
- vendas;
- infraestrutura;
- custos.

# 25. Expansão Nacional

A visão de longo prazo é permitir operação nacional.

Porém, crescimento geográfico sem densidade de estabelecimentos não gera boa experiência.

Por isso, expansão deverá considerar não apenas quantidade de cidades, mas qualidade da cobertura.

---

# 26. Densidade Local

Um dos indicadores estratégicos futuros deverá ser:

> Quantas necessidades locais o VemVer consegue resolver dentro de determinada cidade?

Uma cidade com milhares de lojas incompletas pode ser menos útil do que uma cidade com centenas de estabelecimentos bem cadastrados e relevantes.

Qualidade e densidade deverão caminhar juntas.

```text
      ↓
```

```text
      ↓
ABRIR MODAL / SUBABA
      ↓
ESCOLHER ESTRELAS
      ↓

PUBLICAR
```

# 32. Histórico

- nota;

O VemVer deverá reduzir a distância entre descoberta e ação.

- abrir localização;
- chamar no WhatsApp;
- visualizar produtos;
- avaliar;
- favoritar;
- compartilhar.

O produto não deve criar obstáculos desnecessários entre descoberta e contato.

# 38. Monetização sem Perder Confiança

Regra permanente:

> O consumidor não pode perder confiança nos resultados porque alguém pagou mais.

Planos comerciais poderão melhorar exposição dentro de regras transparentes.

Eles não deverão tornar a busca inútil.

# 39. Plano Gratuito

O plano gratuito possui importância estratégica.

Ele permite:

- entrada de pequenos negócios;
- crescimento do catálogo;
- teste da plataforma;
- redução de barreira de entrada;
- aquisição de lojistas.

# 40. Premium

Planos Premium deverão oferecer valor real.

O lojista deve perceber benefícios claros, e não apenas restrições artificiais no plano gratuito.

Recursos pagos poderão envolver:

- capacidade adicional;
- estatísticas;
- exposição;
- ferramentas;
- gestão;
- recursos avançados.

---

# 41. Patrocinado

O recurso patrocinado poderá aumentar exposição comercial.

Mas deverá sempre respeitar relevância.

A experiência poderá sinalizar claramente resultados patrocinados quando necessário.

Transparência ajuda a preservar confiança.

- múltiplas lojas;
- gestão centralizada;
- equipes;
- permissões;
- relatórios;
- administração de unidades.

---

# 43. Franquias

Franquias poderão representar uma evolução mais avançada do modelo multiunidade.

- desempenho agregado.

Não é apenas responsabilidade técnica.

Um produto confiável precisa proteger:

- usuários;
- lojistas;

- dados;

- uploads;
- automações.

# 46. Privacidade

Dados incorretos prejudicam:

- busca;
- ranking;

- confiança;
- experiência.

# 48. Atualização de Informações

# 49. Escalabilidade

Toda evolução importante deverá considerar crescimento.

---

# 52. Métrica Central

Uma possível direção para métrica principal é:

> Quantas buscas do VemVer resultam em uma descoberta útil?

Uma simples quantidade de usuários não garante valor.

O produto deve medir se está realmente ajudando pessoas a encontrar o que procuram.

---

# 53. Busca sem Resultado

Busca sem resultado deverá ser tratada como informação estratégica.

Quando alguém procura algo que não existe na base, isso pode indicar:

- categoria ausente;
- estabelecimento ainda não cadastrado;
- produto não cadastrado;
- falha de interpretação;
- falha de busca;
- oportunidade comercial.

No futuro, esses dados poderão orientar aquisição de lojistas.

---

# 54. Inteligência Comercial

Com maturidade suficiente, o VemVer poderá oferecer informações valiosas aos lojistas.

Exemplo:

```text
"Muitas pessoas procuraram este produto na sua região."
```

Esse tipo de inteligência pode transformar o VemVer de ferramenta de exposição em ferramenta de decisão comercial.

Qualquer recurso desse tipo deverá respeitar privacidade.

O produto deverá criar ciclos onde consumidores atraem lojistas e lojistas atraem consumidores.

```text
   ↓

   ↓

   ↓

   ↓

   ↓
MAIS LOJAS
```

Esse efeito de rede local é estratégico para o crescimento.

---

# 56. Aquisição de Lojistas

A expansão poderá exigir estratégias ativas para cadastrar estabelecimentos.

# 76. Aparência e Temas

O VemVer deverá oferecer suporte a diferentes modos de aparência tanto para consumidores quanto para lojistas.

As opções planejadas são:

- Automático;
- Claro;
- Escuro.

## Automático

Deverá ser a opção padrão.

Quando selecionado, o VemVer acompanha a preferência de aparência configurada no dispositivo ou sistema operacional do usuário.

Exemplo:

```text
Sistema em modo claro
        ↓
VemVer em modo claro

Sistema em modo escuro
        ↓
VemVer em modo escuro
```

## Tema Claro

O tema claro deverá preservar a identidade visual do VemVer utilizando principalmente:

- branco;
- cinza claro;
- preto;
- grafite;
- laranja como cor principal de destaque.

## Tema Escuro

O tema escuro deverá utilizar principalmente:

- preto;
- grafite;
- cinza escuro;
- textos claros;
- laranja como cor principal de destaque.

A alteração de tema não deverá modificar a identidade da marca.

O laranja continuará sendo uma das principais cores de reconhecimento visual do VemVer.

## Aplicação

O suporte deverá existir tanto no:

```text
APP CLIENTE
```

quanto no:

```text
APP LOJISTA
```

e também deverá ser considerado para a experiência web.

A direção de configuração será:

```text
CONFIGURAÇÕES
      ↓
APARÊNCIA
      ↓
┌─────────────┐
│ Automático  │
│ Claro       │
│ Escuro      │
└─────────────┘
```

## Experiência

A alteração deverá ocorrer sem modificar a estrutura ou funcionalidade das telas.

O usuário deverá poder mudar sua preferência de aparência sem perder:

- navegação;
- estado atual;
- informações;
- configurações;
- identidade visual.

## Arquitetura

Quando essa funcionalidade for implementada, os componentes deverão utilizar um sistema centralizado de tema.

Não devemos criar versões independentes de cada tela apenas para mudar cores.

A interface deverá utilizar tokens, variáveis ou mecanismo equivalente para compartilhar:

- cores de fundo;
- cores de texto;
- bordas;
- cards;
- estados;
- sombras;
- ícones;
- cores de destaque.

Direção conceitual:

```text
DESIGN SYSTEM
      ↓
TOKENS DE TEMA
   ↙         ↘
CLARO      ESCURO
   ↘         ↙
MESMOS COMPONENTES
```

Isso permitirá adicionar ou ajustar temas sem reconstruir a interface.
